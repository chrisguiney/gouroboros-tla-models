# Model and vector coverage of gOuroboros

This audit asks, for every part of gOuroboros: is it covered by a TLA+ model in this repository, by a reference test-vector suite, or by a documented reason it needs neither? Everything else is a gap.

| Input | Revision |
| --- | --- |
| gOuroboros | `origin/main` 1559924b6c1a30596796447888b2f4b31a45eb9c |
| This repository | `main` df5c97d55bf4e0d755e35da548a2432760b113ca |
| ouroboros-mock (fixture corpora, pinned by gOuroboros `go.mod`) | v0.21.3 |

It was done by static reading. No Go test and no TLC run was made for the audit, so a "vectors" or "modelled" verdict says the check exists, not that it passes today.

## Method

- **Inventory.** Every exported function or method with a body, in every non-test package outside `internal/`, `testdata` and `cmd`: 3,714 functions in 41 packages. A function is *logic-bearing* if its body has at least one `if`, `for`, `range`, `switch` or `select`; 1,695 are. The rest (getters, constructors, straight-line wrappers) are not classified one by one.
- **Classes.** Each logic-bearing function sits in exactly one item, and each item has exactly one class:
  - **modelled:** a model here names the invariant the function must keep;
  - **vectors:** a pure computation checked against reference vectors (real-chain CBOR, upstream goldens, published crypto vectors, the Blueprint ledger corpus, E34). Round-tripping our own encoding does not count, and neither do hand-written expectations;
  - **caller contract:** gOuroboros keeps no state for it, the caller (Dingo) owns the logic, and the contract is written down (godoc, a model README, `ARCHITECTURE.md`);
  - **gap:** none of the above.
- **Per-function map.** [coverage/functions.tsv](coverage/functions.tsv) lists all 1,695 logic-bearing functions with their class and item.
- **Model notes.** Every "Not modelled" / "Not covered" note in `specs/*/README.md` is classified the same way.

## Findings across packages

These shape how far the "vectors" and "modelled" verdicts reach.

1. **The Blueprint ledger corpus reaches only Conway rule functions.** ouroboros-mock v0.21.3 `conformance/validation_rules.go` lists 103 `conway.*` rules and no rule from any other era, even for the Shelley, Mary, Alonzo and Babbage titles. Shelley-to-Babbage and Dijkstra `Validate*` rules get no ledger vectors. The corpus has no Byron or Dijkstra vectors at all.
2. **The corpus checks neither fees nor transaction size.** The same file excludes `UtxoValidateFeeTooSmallUtxo` and `UtxoValidateMaxTxSizeUtxo` (lines 114-148), and `ledger-utxo` models the minimum fee as 1. Enabling both rules (by appending them to the mock's exported rule lists in a scratch test) leaves all 2,575 vectors passing, and a rule that always fails makes 2,409 fail, so the rules do run. They still pin nothing: every one of the 2,410 transactions that reaches them overpays the minimum fee by at least 15,825 lovelace, none is near `maxTxSize` (16,384), and the corpus has no FeeTooSmall or MaxTxSize rejection. To make them useful ouroboros-mock needs: the two rules in its lists (its "CBOR encoding differences" reason is stale; `TxSize` uses the received bytes), a `HarnessConfig` hook for extra rules, per-era parameters so pre-Conway titles use their era's fee rule (Babbage has no reference-script fee), and vectors at the fee and size boundaries. The formulas are now pinned by the cardano-ledger golden tests listed under "Closed since the audit".
3. **Most Conway GOV rules are not pinned by the corpus.** The harness runs its own phase-1 validator before `common.VerifyTransaction`. The `ledger-governance` README records that 15 of the 17 GOV rules can be made to return nil with every vector still passing, so those rules are classed as gaps, not vectors.
4. **Some model-driven Go tests are not on gOuroboros `main`.** The selection, validation and envelope tables (`consensus`), the witness table (`ledger-witnesses`), the hash-cache tests (`ledger-hash-cache`), the certificate lifecycle test (`ledger-shelley`) and the Leios ledger cells (`ledger-leios`) live on open branches (see [PRS.md](PRS.md)). Those items are still classed *modelled*, because the invariant exists here, but nothing on `main` ties the code to it.
5. **Reference goldens that ouroboros-mock already ships go unused.** No gOuroboros test reads:
   - cardano-ledger `translations.cbor` (Babbage, Conway, Dijkstra script-context goldens);
   - cardano-ledger `pparams.json` and `pparams-update.json`;
   - `fixtures/tachys/leader_selection.json`;
   - the ouroboros-consensus node-to-node `Block_*`, `Header_*`, `GenTx_*` and `GenTxId_*` goldens, outside the conformance harness;
   - the further ouroboros-consensus `Query_*`/`Result_*` goldens beyond the handful `localstatequery` uses.

   Wiring these in is the cheapest way to turn gaps into vectors.
6. **Thin vector suites.** KES has 2 vectors (Sum6, periods 0 and 5, one seed). VRF has 29 must-accept vectors and no must-reject ones. No ouroboros-network mini-protocol CDDL goldens exist in ouroboros-mock, so the protocol message codecs rest on a few real captures (chain-sync, leios-notify, some local-state-query).
7. **Known defects still on `main` that a model already catches:**
   - Shelley envelope refuses block 0 after Origin (DRIFT C4, `ShelleyEnvelopeNoOriginBug`).
   - Byron envelope accepts a repeated slot and either block number for an EBB (DRIFT C5).
   - Byron delegation's own-entry rule (DRIFT C10, `ByronDelegationOwnEntryBug`).
   - Byron `maxTxSize` is not checked (DRIFT L6).
   - `DijkstraLeiosCertificate.Validate` requires exactly Nc seats (DRIFT L9).
8. **Stale "Not modelled" notes.** `specs/consensus/README.md` still lists Tachys and the Byron delegation map as not modelled; `consensus-tachys` and `ledger-byron/ByronDelegation.tla` now model them. The `pipeline-cbor` note on the retained-CBOR byte budget predates `PipelineLifecycle.tla` `BudgetMatchesActive`.
9. **`ValidateHeader` is modelled; the production path is not.** Dingo validates headers through `ledger.VerifyBlock` (DRIFT C15). The `consensus-eras` check-order model covers `consensus.ValidateHeader`, so the modelled order and overlay handling are not those of the path in production.

gOuroboros 1559924b; model repo gouroboros-tla-models; ouroboros-mock v0.21.3. Static reading only; no tests run.
